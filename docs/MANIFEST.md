This manifest defines the planned repository. Each file has one primary responsibility. Build-step references match `STEPS.md`. Public contracts are the intended stable interfaces; framework callback signatures will be confirmed against the installed LiveKit version during Step 0 rather than guessed.

## Contract conventions

- All patient-data service methods require a trusted `call_id` and derive patient identity from server-side session state. No public tool or service method accepts an LLM-selected `patient_id`.
- Domain methods return typed outcomes for expected business states and raise a small typed domain-error hierarchy for exceptional/unauthorized states.
- All write operations are idempotent where retried; appointment creation and slot consumption are one database transaction with a DB-level uniqueness constraint.
- Agent prompts contain no patient records or secrets. Tool outputs contain only the minimum typed facts required for the current spoken response.
- No raw audio or raw transcript is persisted. Raw verification values are parsed and redacted before retained conversation history or handoff contexts. Application logs and audit events contain metadata and masked summaries only.
- FastAPI and LiveKit tools share the same `ClinicService` instance/interface. FastAPI is not an internal tool transport.
