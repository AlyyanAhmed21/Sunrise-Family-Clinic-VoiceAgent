## Scope notes
- The official brief is authoritative. This project is a synthetic-data assessment prototype, not a claim of HIPAA certification or a production-compliant deployment.
- No raw transcript or audio persistence is planned. Conversation text exists only transiently in the live session and must be redacted before entering retained chat history or handoff context.
- Optional vendor-side recording/observability controls will be checked and disabled where exposed. Data necessarily transits the selected room, STT, LLM and TTS vendors; this transit and the production BAA requirement must be documented honestly.

## Review amendments (2026-11-24)

- **R-04 clarification:** `ALLOW_TIME_SIMULATION=false` by default. It may be enabled only from trusted job metadata, never caller input.
- **R-07 clarification:** LiveKit session preemptive generation is disabled by default. `VerificationAgent` is a model-free `NoModelAgent` with agent-level preemptive opt-out and an `llm_node` that never invokes a model. All other agents use `GuardedAgent.llm_node` to redact a COPY immediately before every model call (preemptive, normal and tool-follow-up). Redact inbound content before retaining it in history or handoff context. Verification state remains server-side. `StopResponse`-dropped turns must not be relied on to persist verification state.
- **R-40 clarification:** configure `session.start(record=False)`, LiveKit Cloud project-level Agent observability OFF, and Deepgram STT/TTS `mip_opt_out=True` (model-improvement opt-out), subject to Step 0 confirmation of current plugin/provider semantics. Document what is actually configured and vendor transit.
- **R-58:** detect volunteered identifiers outside verification, including spoken-year DOBs, and route to verification before disclosure/action.
- **R-05/R-06 parser cases:** include “last four”, “one moment”, “oh”, “double four”, `3344`, `33 44`, `3-3-4-4`, ordinal DOBs, spoken-year DOBs and rejection of more than four SSN digits.
- **R-50/R-54 scope:** Docker is not a required deliverable; do not add a Dockerfile or Docker CI build. Production direction may be documented as a container image plus PostgreSQL.
